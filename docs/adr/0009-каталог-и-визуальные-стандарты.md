# ADR 0009: Каталог товаров и визуальные стандарты (Промт 8)

Дата: 2026-11-12
Статус: принято

## Контекст

Промт 7 оставил платформу с реальной аутентификацией, но без
бизнес-данных: все разделы ролей — осмысленные заглушки. Промт 8
двигает продукт по двум осям сразу:

1. **Реальный каталог товаров** — первый бизнес-экран покупателя:
   категории, товары, предложения продавцов, поиск, фильтры,
   сортировка, пагинация. Каталог — витрина: его надо показывать
   быстро и красиво, корзина и заказы — Промт 9.
2. **Визуальное качество** — аудит по 10 критериям и 14 экранам
   показал системные проблемы пустых экранов (тексты про «будущее
   API», кричащие кнопки выхода, отсутствие действий) и потребовал
   закрепить правила, обязательные для всех следующих промтов.

## Решение

### Каталог: модель данных

```
Category (slug, name, icon, sortOrder)
   └── Product (categoryId, name, unit, description, images: JSON)
          └── ProductOffer (productId, organizationId, priceKopecks,
                            stock, minQuantity, badge?, isPerishable)
```

- **Цена — в ProductOffer, не в Product**: один товар предлагают
  несколько организаций, у каждой своя цена, склад и минимальная
  партия. «Лучшая цена» товара = min(priceKopecks) по предложениям.
- **`images` — JSON-массив URL-строк** (SQLite не имеет нативных
  массивов). До Промта 9 картинки не загружаются — UI показывает
  детерминированные пастельные заглушки (`tokens/placeholder.ts`):
  тон циклится по индексу, одинаковый в обеих темах (фотография
  остаётся «светлой» и в тёмной теме).
- **`badge` — строка или null** (`hit` → «Хит»): набор расширяется
  без миграций; `isPerishable` → бейдж «Скоропорт».
- Миграция `20261112020332_add_catalog`; каскады по внешним ключам.

### Каталог: API

Четыре **публичных** маршрута (как health, без Bearer — витрину
можно листать до регистрации; корзина и заказы потребуют входа):

| Маршрут                                | Что возвращает                  |
| -------------------------------------- | ------------------------------- |
| `GET /api/catalog/categories`          | категории с productCount        |
| `GET /api/catalog/products`            | страница товаров с bestOffer    |
| `GET /api/catalog/products/:id`        | товар + все предложения         |
| `GET /api/catalog/products/:id/offers` | предложения по возрастанию цены |

- Поиск, фильтр цены и сортировки считаются **в сервисе в памяти**:
  объём демо-каталога (30 товаров) это позволяет, а честный
  `lower()` для кириллицы в SQLite через LIKE недоступен
  (регистронезависимость только для ASCII). Полноценный
  полнотекстовый поиск — Промт 9 (PostgreSQL).
- Сортировки: `popular` (больше предложений выше), `price-asc`,
  `price-desc`, `name` (localeCompare ru). Фильтры цены — целые
  рубли в запросе, копейки в ответах.
- Seed идемпотентен: 6 категорий, 30 товаров, 90 предложений трёх
  организаций (`apps/api/src/seed/catalog-data.ts`).

### Каталог: клиент

- **TanStack Query — единственный новый пакет Промта 8**
  (`@tanstack/react-query`): `useQuery` для категорий и детали,
  `useInfiniteQuery` для пагинации списка. QueryClient в корневом
  layout, staleTime 5 минут, retry 1.
- Типы контракта — `packages/types/src/catalog.ts`; клиент —
  `apps/mobile/src/services/api/catalogApi.ts`.
- Вкладка «Каталог» заменила «Главную» у покупателя
  (`FIRST_SECTION.customer = 'catalog'`): 5 вкладок, первая —
  витрина.
- Экран товара `/customer/product/[id]`: галерея-карусель,
  ProductDetailCard с предложениями, нижняя панель с количеством
  (минимум = минимальная партия) и кнопкой «В корзину · сумма».
  Корзины нет — по нажатию тост «Корзина появится в следующем
  обновлении».

### Визуальные стандарты (обязательны от Промта 8)

Закреплены в AGENTS.md и проверяются скриптом
`pnpm lint:visual` (`scripts/check-visual-rules.mjs`):

- красный (#FF0000/#E74C3C/#DC3545) запрещён; опасное — терракота;
- ActivityIndicator/Spinner запрещены — загрузка только Skeleton;
- эмодзи в UI запрещены — иконки Lucide;
- рамки вместо теней, зоны касания ≥ 48, основной текст ≥ 17pt,
  WCAG AA, тёмная тема — полноценная, не инверсия;
- роли имеют свой акцент: покупатель — фото-витрина, владелец —
  цифры, оптовик — партии и цены, перевозчик — маршруты.

По итогам аудита Части A переработаны: профили (карточка «Контекст
работы», спокойная текстовая кнопка выхода вместо кричащего блока),
пустые ленты (обещание + действие «Переключить контекст»), экраны
входа (иконки-якоря на пастельных плашках, сгруппированные ссылки).

### Golden-скриншоты

Эталонные скриншоты ключевых экранов (вьюпорты 360/390/430, светлая
и тёмная темы) хранятся в `download/промт8/golden/` и переснимаются
после каждого визуального изменения. Pixelmatch-сравнение с
допуском в CI — открытое предложение, не реализовано (см. «Открытые
вопросы»).

## Последствия

- Модель каталога расширяется в Промте 9 без ломки: корзина и
  заказы ссылаются на ProductOffer (цена фиксируется в момент
  заказа), у продавца появится управление своими предложениями.
- Публичность каталога — осознанный размен: листать витрину можно
  без входа, но любые действия (корзина, заказ) — только с сессией.
- JS-агрегации в сервисе — временный компромисс демо-объёма;
  миграция на PostgreSQL переносит их в SQL без изменения контракта
  API.

## Открытые вопросы

- Pixelmatch-сравнение golden-скриншотов в CI с допуском ≤ 0,5% —
  предложено, не подтверждено: нужен стабильный headless-рендер.
- Индексация поиска (FTS5/PostgreSQL) и фильтрация по признакам
  (только скоропорт, только хиты) — Промт 9.
- SecureStore вместо AsyncStorage для refresh-токена — Промт 9.
