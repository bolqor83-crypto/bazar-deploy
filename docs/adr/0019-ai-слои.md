# ADR 0019: AI-слои — почему сейчас Layer 0+1, а LLM потом

**Статус:** принят (Промт 18)
**Контекст:** «AI Market Intelligence» для оптового рынка звучит
как «подключим GPT». Но данные живут в своей БД, а пользователь —
продавец на рынке в 4 утра, которому нужно быстро понять: что
дорожает, что берут, что странно. Продукт — демо без внешних
ключей и платных API (ограничение проекта). Слои позволяют
двигаться инкрементально и получать пользу на каждом.

## Модель: четыре слоя

| Слой                     | Что                                                                 | Технология                    | Статус                     |
| ------------------------ | ------------------------------------------------------------------- | ----------------------------- | -------------------------- |
| **0. Данные**            | Агрегация из БД: тренды цен, объёмы, активность, аномалии (Z-score) | SQL/Prisma, кэш 5–15 мин      | **Промт 18, C**            |
| **1. Дашборды**          | Визуализация Layer 0 для продавца                                   | свой UI, SVG-графики          | **Промт 18, D**            |
| **2. Рекомендации**      | «Закажи томаты — к пятнице дорожает»                                | правила/модели поверх Layer 0 | отложено (следующий промт) |
| **3. LLM-интерпретация** | Ответы на вопросы словами, объяснения                               | внешний LLM API               | отложено (требует ключей)  |
| 4. Действия              | «Оформить заказ?» с подтверждением                                  | Layer 2/3 + транзакции        | отложено                   |

## Почему Layer 0+1 сейчас, а 2+4 потом

1. **Никакой магии без фундамента.** Рекомендации (Layer 2) и
   LLM-объяснения (Layer 3) бессмысленны без честной агрегации:
   LLM, поверх кривых данных, уверенно врёт. Layer 0 —
   проверяемая математика: AVG, SUM, Z-score.
2. **Быстро, дёшево, объяснимо.** SQL-агрегация выполняется
   миллисекунды, не стоит денег на внешних API, и каждое число на
   дашборде можно проверить запросом. Для демо-продукта это
   важнее «вау» от LLM.
3. **Ограничения проекта.** Внешний LLM API = ключи, сеть,
   стоимость, latency и приватность данных клиентов. Запрещено
   ТЗ промта 18; когда продукт пойдёт в прод — слой 3 можно
   добавить, не трогая 0–1.
4. **Пользователю сначала нужна картина, потом советы.** Продавец
   сам знает своё дело: ему нужны факты («огурцы +12% за неделю»),
   а решать он будет сам. Рекомендации без его доверия к данным —
   мусор.

## Решения Layer 0 (Промт 18, C)

- `GET /api/market/trends` — средние цены и изменение % по
  категориям (день/неделя/месяц). **Публичный**: агрегаты по
  публичному каталогу не раскрывают частное.
- `GET /api/market/volumes` — объёмы заказов по товарам. Публичный.
- `GET /api/market/users` — активность по ролям. Только для
  аутентифицированных продавцов (агрегировано, без персон).
- `GET /api/market/anomalies` — Z-score > 2 по ценам/объёмам.
  Только продавцы.
- Кэш in-memory с TTL (5–15 мин): дашборд не должен молотить БД
  на каждый заход; данных немного, Redis не нужен (одно
  инстансо на Render free tier).
- Аномалии — статистика, не прогноз: Z-score по последним
  N дням против baseline.

## Решения Layer 1 (Промт 18, D)

- Дашборд продавца `(tabs)/(wholesale)/analytics`: тренды
  (TrendCard), объёмы (простой SVG bar chart — без тяжёлых
  библиотек), топ-товары, аномалии.
- Цифры крупные (numberL), tabular-nums; рост — success
  (зелёный), падение — terracotta (не красный).
- Состояния: skeleton / empty («Продажи появятся, когда будут
  заказы») / error+retry.

## Отложено (v2+)

- Layer 2: рекомендательные правила + объяснение «почему».
- Layer 3: LLM-интерпретация трендов и аномалий (внешний API).
- Layer 4: действия из рекомендаций с подтверждением человека.
- Прогнозирование (временные ряды) — требует истории длиннее
  демо-периода.
