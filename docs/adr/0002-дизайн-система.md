# ADR 0002: Дизайн-система (токены, темы, компоненты)

- **Статус:** принято (Промт 2)
- **Дата:** 2026-11-10

## Контекст

Приложение работает в жёстких условиях: пользователь на рынке в 4–14 утра, в
перчатках, при слабом свете и слабом сигнале. Без единой дизайн-системы каждый
новый экран рождал бы собственные цвета, размеры и паттерны загрузки, и
операционный контекст быстро бы «разъехался».

Требования зафиксированы в AGENTS.md: зоны нажатия ≥ 48×48 pt, body ≥ 17 pt,
высокий контраст (WCAG AA), красный запрещён (только янтарь и терракот),
спиннеры запрещены (только Skeleton).

## Решение

### Токены (`packages/ui/src/tokens/`)

- **colors.ts** — палитры `{ light, dark }` с одинаковыми ключами. Семантические,
  а не «сырые» имена: `primary`, `primarySoft`, `onPrimary`, `textSecondary`,
  `danger` (терракота), `accent` (янтарь) и т.д.
- **typography.ts** — 9 вариантов (display…micro), шрифт Inter через
  `@expo-google-fonts/inter` (400/500/600/700). `mono` → `fontVariant:
  ['tabular-nums']` для сумм и количеств.
- **spacing.ts** — 7 значений (xs 4 … xxxl 48), ничего сверх.
- **radii.ts** — sm 12 / md 16 / lg 20 / pill 999.
- **shadows.ts** — три уровня в light; в dark теней нет, компоненты отделяются
  границей `border` 1 px.
- **animations.ts** — fast 150 / base 220 / slow 300 мс; пружины base {200, 22, 1}
  и quick {300, 26, 1}; easings outQuad/outCubic.
- **haptics.ts** — tap → impact(Light), success/warning/error → notification,
  selection → selectionAsync; троттлинг 150 мс на уровне модуля; на web — no-op.

### Темы (light / dark / system)

- Стор `useThemeStore` (Zustand + persist в AsyncStorage, ключ `bazar.theme.mode`).
- Режим `system` следует за Appearance через `useSystemSchemeStore`.
- `useTheme()` возвращает `{ mode, isDark, colors, spacing, radii, typography,
  shadows }` — единственная точка доступа к токенам.
- Автоматическое переключение на тёмную тему в 4:00–7:00 **не реализовано** и
  не планируется: тема — настройка пользователя, а не расписания.

### Компоненты (12)

`Text`, `Button`, `IconButton`, `Input`, `Card`, `Badge`, `Skeleton`,
`EmptyState`, `ErrorState`, `Divider`, `Dialog` (нижний шит), `Toast`
(провайдер + очередь). Общие правила:

- Text — единственный путь к тексту: гарантирует Inter и контраст.
- Button: sm 40 / md 48 / lg 56; loading — три пульсирующие точки (не спиннер);
  disabled — прозрачность 0.5 и блокировка нажатия.
- IconButton: 44/48/56 + hitSlop 8; accessibilityLabel обязателен.
- Input: подпись сверху; фокус — граница primary 2 px; ошибка — граница danger
  и текст под полем; подсказка скрывается при ошибке; состояние ошибки
  озвучивается через accessibilityHint (AccessibilityState.invalid отсутствует
  в типах RN 0.88).
- Dialog: RN Modal + Reanimated (пружина base), закрытие таймингом 220 мс,
  drag-to-dismiss за «ручку», `accessibilityViewIsModal`.
- Toast: сверху с учётом safe area, длительность 3000 мс по умолчанию, очередь,
  контейнер `box-none` — не блокирует UI.
- Провайдер `BazarUIProvider` = SafeAreaProvider + ThemeProvider + ToastProvider.

### Контраст WCAG AA

Тест `contrast.test.ts` вручную (без библиотек) считает относительную яркость
и коэффициент контраста по формулам WCAG 2.1 для 11 смысловых пар в обеих
темах; порог 4.5:1. Ради AA исходные hex макета скорректированы:
light `textSecondary #666D64`, `textMuted #6C716A`, `accent #8A6519`,
`danger #9F4C3B`, `success #2B7B58`, `info #2F69AB`; dark `textMuted #878E84`.
`onAccent` в light — белый: тёмный текст на янтаре нарушает контраст сильнее.
`success` близок к `primary` — разведение признано излишним.

Фактические коэффициенты: см. `download/контраст-таблица.txt` (все пары PASS).

## Известные ограничения (принятые по отчёту Промта 2)

1. **Не-текстовой контраст рамок в покое < 3:1** (`border` #E4EAE4 на фоне).
   Функциональные рамки (фокус, ошибка) контрастны; декоративные — нет.
   Вынесено на полевые испытания.
2. **Отключены правила ESLint `react-hooks/immutability` и `react-hooks/refs`** —
   ложные срабатывания на shared-значения и ворклеты Reanimated.
   ВРЕМЕННО: вернуть при появлении совместимого линт-плагина Reanimated.
3. iOS/Android-поведение (хаптика, сплэш, safe area) проверяется пользователем
   на устройстве; в песочнице проверяется только web.

## Последствия

- Все новые экраны обязаны использовать только токены и компоненты `@bazar/ui`;
  «сырые» цвета и размеры в экранах запрещены.
- Витрина `/dev/design` доступна только в dev-сборках (`__DEV__`), в проде —
  редирект на главную.
- Состав компонентов расширяем (Checkbox, Radio, Select — следующих промтов);
  изменения токенов требуют пересчёта контраста.
