# ADR 0015: Иконки, точка наличия, компактная сетка каталога, группировка заказов

**Статус:** принят (Промт 15)
**Контекст:** после тюнинга 14b (ADR 0014) пользователь дал два
императива: (1) категории, роли и инструменты узнаются с первого
взгляда — монохромные Lucide-глифы этого не давали; (2) «несколько
заказов одного продавца должны собираться вместе, чтобы не было
разрозненно» — плоский хронологический список покупателя скрывал
структуру его отношений с контрагентами.

## Решения

### 1. Цветные SVG-иконки — 16 штук, палитра отдельно от UI-токенов

- `packages/ui/src/icons/`: 6 категорий (овощи, фрукты, молочное,
  зерно, тара, зелень), 4 роли (покупатель, оптовик, перевозчик,
  владелец точки), 6 инструментов (заказы, доставка, склад,
  аналитика, финансы, товары).
- Собственные `Svg`-компоненты на react-native-svg (viewBox
  `0 0 24 24`, размеры 24/32). Без `currentColor` — цвет зашит
  палитрой.
- `icons/palette.ts` — 17 значений, **отдельно от `tokens/colors.ts`**:
  эти цвета рисуют иллюстрации, а не текст и рамки, и не проходят
  контраст-тесты интерфейса. Правило «свежесть через цвет, а не
  через радугу»: цветом выделено только то, что символизирует
  продукт или роль; tab bar и кнопки остаются монохромными.
- Ролям отданы «фирменные» цвета: покупатель — изумруд `#0E7C5A`,
  оптовик — золото `#D4A847`, перевозчик — синий `#5C8DC4`,
  владелец точки — тёплый беж `#C89B6C`.
- В dark-теме иконки те же: насыщенности хватает на фоне #161917.

### 2. StockDot — точка наличия в карточке

- `<StockDot level size>`: круг 12×12, уровни in/low/out →
  success/accent/textMuted, обводка 2px (белая в light, surface
  в dark), позиция — левый верхний угол фото.
- a11y сохранена: `accessibilityLabel` «Наличие: В наличии /
  Мало осталось / Нет в наличии» — из скриншота информация
  выведена в озвучку.
- Полный текст наличия остаётся в `<StockIndicator>` на детальной
  странице — карточка не дублирует.

### 3. Компактная ProductCard каталога

- На 390: фото 173 (1:1, bleed) + 12 + заголовок 46 (2 строки) +
  4 + цена 24 + 16 = **275±5** — против ~430 прошлой версии
  (subtitle, продавец, minQuantity, текст наличия).
- Из карточки убраны: subtitle, продавец, minQuantity, текст
  наличия (заменён точкой). Пропсы сохранены — карусель похожих
  и другие режимы используют их.
- Правило 14b сохранено: тень вместо границы, фото решает.

### 4. Адаптивная сетка 2/3 + SortPicker compact

- `TABLET_BREAKPOINT = 600`: < 600 — 2 колонки, ≥ 600 — 3
  (планшет, широкий web), `key={numColumns}` пересоздаёт
  FlatList при повороте. Skeleton повторяет раскладку (2×2 /
  3×2).
- `SortPicker compact` перенесён в заголовок секции «Все товары
  (N)» — вертикальный пикер-лист уходит, сортировка всегда на
  виду, один tap.

### 5. Группировка заказов по контрагенту — UI-only

- `groupOrdersByParty()` (`apps/mobile/src/utils/groupOrders.ts`):
  чистая функция, группы {party, orders, count, activeCount,
  totalSum (без CANCELLED), latestCreatedAt, hasActive};
  сортировка групп — активные выше, затем свежесть; внутри группы
  createdAt DESC. Дженерик по `getParty` — покупатель группирует
  по продавцу, продавец по покупателю.
- `<OrderPartyGroup>` (ui): заголовок 64 — аватар-инициалы 32,
  имя h3, мета «N заказов · сумма» табличными цифрами, чип accent
  «N активных», шеврон 180ms; свёрнуто — только заголовок; a11y
  role button + state expanded; зоны ≥ 48×48.
- Экраны customer/store/wholesale: режим «По продавцам» (у
  продавца «По покупателям») — по умолчанию, «По дате» — прежний
  плоский список (регрессия закрыта golden orders-light-390).
  Выбор персистится в AsyncStorage `bazar.orders.viewMode`.
  Фильтрация применяется ДО группировки. Состояния expanded —
  локальный Map по party.id, группы с hasActive развёрнуты.
- **Правило Промта 9 сохранено: один Order = один продавец.**
  В БД ничего не меняется, нумерация BZ-YYYY-NNNNNN прежняя;
  группировка — только представление. GET /api/orders и
  /api/seller/orders уже отдают контрагента (seller/buyer) —
  новых endpoints не потребовалось.
