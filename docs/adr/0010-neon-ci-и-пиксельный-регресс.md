# ADR 0010: PostgreSQL на Neon, GitHub CI и пиксельный регресс (Промт 9)

Дата: 2026-11-13
Статус: принято

## Контекст

Промт 8 оставил платформу на SQLite: каталог и аутентификация
работали, но база жила файлом рядом с процессом — миграции,
CI и командная работа требовали настоящей СУБД. Промт 9 ставит
три инфраструктурные задачи:

1. **Миграция на PostgreSQL** — управляемый cloud-провайдер,
   бесплатный тир, регион близкий к пользователям (ЕС).
2. **GitHub как источник истины** — приватный репозиторий,
   push из песочницы без токена в `.git/config`, CI с секретами.
3. **Пиксельный регресс** — golden-скриншоты в CI: вёрстка
   не должна молча меняться между промтами.

Плюс первые транзакционные сценарии домена: корзина и заказы
(резерв склада, группировка по продавцам, отмена) — им нужны
интерактивные транзакции, которых нет за пулом соединений.

## Решение

### Neon: одна БД проекта, две строки подключения

```
DATABASE_URL_POOLED  → PgBouncer (transaction-pooling) — serverless
DATABASE_URL_DIRECT  → прямой TCP — миграции, NestJS-рантайм, e2e
```

- **Prisma-схема** держит обе: `url` (pooled) + `directUrl` (direct).
  `db push`/`migrate` идут через directUrl автоматически.
- **PrismaService (рантайм) выбирает DIRECT**: интерактивные
  `$transaction` (ротация refresh-токенов, stock-резерв заказа,
  отмена с возвратом на склад) не поддерживаются за PgBouncer
  transaction-pooling. Pooled остаётся заделом для serverless
  (Промт 10, Render).
- **Тестовая БД — `bazar_test` в том же проекте Neon**: e2e-набор
  переписывает путь URI (`/neondb` → `/bazar_test`), демо-данные
  основной базы не затрагиваются. `--runInBand` обязателен.
- **Архив SQLite**: миграции Промтов 7–8 перенесены в
  `_sqlite-migrations-backup`, новые миграции — PostgreSQL-only.
  SQLite остаётся локальным fallback без сети.

### Надёжность e2e в CI: терминация сессий + ретраи

`prisma db push --force-reset` на bazar_test однажды упёрся в
deadlock (CI-ран №9: DROP/ALTER против висящей сессии). globalSetup
теперь: (1) `pg_terminate_backend` всем чужим сессиям тестовой БД
через `prisma db execute`, (2) до 3 попыток сброса с паузой 5 с —
deadlock в Postgres транзиентен.

### GitHub: cred-helper без токена в конфиге

- Репозиторий `bolqor83-crypto/bazar` (private), ветка `main`.
- Push из песочницы: `git config credential.helper` указывает на
  `secrets/git-cred-helper.sh` — скрипт читает PAT из файла вне
  репозитория, в `.git/config` только путь.
- Секреты Actions (Neon URI ×2, JWT) загружены libsodium-sealed
  box ( репозиторий их не видел в открытом виде.
- Workflow `Проверка качества`: три job — `quality`
  (lint+typecheck+unit), `e2e на PostgreSQL (Neon)` (bazar_test,
  после quality), `pixelmatch golden` (после quality, параллельно
  e2e — разные базы, блокировки не пересекаются).

### Pixelmatch: golden как контракт вёрстки

- **Набор**: 22 записи (17 Промт 8 + 5 Промт 9: корзина светлая/
  тёмная, checkout, список заказов, карточка). Вьюпорты 360/390/430,
  темы light/dark, манифест `docs/visual-golden/manifest.json`.
- **Tolerance 0.5%** от площади: 1 пиксель шума не роняет CI,
  заметный блок (100×100 = 0.76%) — роняет. Границы проверяет
  самотест (`pixelmatch-selftest.mjs`, фильтр `VISUAL_ONLY`).
- **Детерминированность**:
  - `prefers-color-scheme` вместо тумблера — тема повторяема;
  - анимации/каретка отключаются инжект-стилем;
  - маски динамических зон (`pixelmatch-config.json`): тосты,
    shimmer-скелетоны, аватары, время — скрываются `visibility:
hidden` (с Промта 9 маска реально работает: у Toast появился
    `testID="toast"`);
  - **корзина Ивана сбрасывается к 1 позиции через API** перед
    съёмкой user-экранов (DELETE /cart + первый товар каталога ×2):
    badge таб-бара и экраны корзины не зависят от истории прогонов;
  - открытие карточки заказа — до 3 кликов с контролем по URL
    (медленный CI: React-гидратация опаздывает за появлением DOM).
- **Переснятие golden — только вручную** (`pnpm golden:update`,
  точечно — `golden-one.mjs`) с обязательным review `git diff`
  и коммитом: golden меняется только вместе с осознанным
  изменением вёрстки.

### Корзина и заказы: транзакционные правила (Части D+E)

Реализовано в том же промте, решения домена — кратко:

- **Cart/CartItem** на `(userId, organizationId)`: контур задаётся
  заголовком `X-Organization-Id` (пусто — розничная корзина).
  Пустая строка вместо NULL — уникальный индекс не конфликтует.
- **Заказ** = `Order/OrderItem/OrderEvent` + `OrderCounter`
  (нумерация `BZ-YYYY-NNNNNN`, атомарный инкремент).
- **Создание** — одна транзакция на все группы продавцов: нехватка
  stock хотя бы по одной позиции откатывает весь заказ.
- **Отмена** (buyer/seller, статусы PENDING/CONFIRMED) возвращает
  stock и пишет событие `CANCELLED` в ленту `OrderEvent`.

## Последствия

- e2e-тесты стали сетевыми: время прогона выросло с ~30 с до ~4 мин
  (Neon eu-central-1 + Argon2id), `testTimeout` поднят до 30 с.
- CI-минуты GitHub тратятся на 3 job (~10 мин на push) — приемлемо
  для бесплатного тира на текущем размере команды.
- Golden требует дисциплины: любое изменение вёрстки — осознанный
  коммит PNG. Зато визуальные регрессии ловятся до ревью.
- Прямой dependency от доступности Neon: падение региона = красный
  CI. SQLite-fallback остаётся для локальной работы без сети.

## Что НЕ сделано (сознательно)

- Render-деплой — Промт 10 (pooled-URI уже готов).
- Seller-флоу подтверждения заказов, платежи, доставка, S3-картинки,
  FTS-поиск, избранное, рейтинг — вне рамок промта.
