# ADR 0004: Аутентификация, сессия и защита маршрутов

- **Статус:** принято (Промт 4)
- **Дата:** 2026-11-11

## Контекст

Приложение выросло из оболочки с моками в структуру с ролевой навигацией.
Следующий шаг — вход пользователя и защита экранов. Реального бэкенда ещё
нет (он появится в Промте 6), поэтому аутентификация реализована на
мок-бэкенде поверх AsyncStorage — но с production-правилами безопасности:
пароли не хранятся в открытом виде даже в моке.

## Решение

### Модель данных (`packages/types/src/auth.ts`)

```ts
type AuthUser = {
  id: string;
  phone: string; // E.164: +7 и 10 цифр
  name: string;
  createdAt: string;
  memberships: Membership[]; // из ADR 0003
};

type Session = {
  userId: string;
  token: string; // псевдо-токен (UUID), не JWT
  issuedAt: string;
  expiresAt: string; // 7 дней
};

type AuthState = 'unknown' | 'authenticated' | 'unauthenticated';
```

`unknown` — сессия ещё не проверена (старт приложения). До выхода из
`unknown` показывается скелетон, сплэш не скрывается.

### Хеширование паролей

- `expo-crypto` SHA-256 от строки `password + salt`.
- Соль — 16 случайных байт (hex) на пользователя.
- Разные пользователи с одинаковым паролем → разные хеши.
- Пароль никогда не покидает экран ввода, не логируется, не попадает
  в аналитику.

### Мок-бэкенд (`apps/mobile/src/services/authMock.ts`)

// MOCK ONLY. Реальный бэкенд — Промт 6.

- Пользователи: `bazar.auth.users` → `Record<phone, UserRecord>`, где
  `UserRecord = AuthUser & { passwordHash, salt }`.
- Сессии: `bazar.auth.sessions` → `Record<token, Session>`.
- Логин-OTP: `bazar.auth.otp.<phone>` → `{ code, expiresAt }`.
- OTP сброса: `bazar.auth.reset-otp.<phone>` — отдельный префикс,
  коды не взаимозаменяемы.
- Индекс OTP-ключей `bazar.auth.otp.index` — для полной очистки при logout.
- Задержка сети 300–700 мс только в браузере; на SSR и в тестах — 0.
- Мок-пользователь Иван Петров (+79001234567 / qwerty123) создаётся при
  первом обращении к сервису, членства — из моков Промта 3.
- OTP: 6 цифр, TTL 5 минут, одноразовый. Код печатается в консоль
  (`console.warn`, префикс `[MOCK OTP]`) **только в `__DEV__`**.

### Store (`apps/mobile/src/stores/authStore.ts`)

- Персист — только `{ userId, token }` под `bazar.auth.session`;
  полные данные восстанавливаются через `getSession`.
- `hydrate()` на SSR (`typeof window === 'undefined'`) — сразу
  `unauthenticated`, без обращения к хранилищу.
- После login / register / loginWithOtp — синхронизация `contextStore`:
  контекст по приоритету членств `wholesale → store_owner → carrier →
customer`; без членств — customer.
- `logout()` — полная очистка: сессия на «сервере», все OTP-ключи,
  `bazar.auth.session`, `bazar.context.active`, оба стора.
- Ошибки поглощаются и пишутся в `error` человекочитаемым текстом;
  наружу исключения не летят. Коды `AUTH_USER_NOT_FOUND` и
  `AUTH_INVALID_PASSWORD` показываются одинаковым текстом — не
  раскрываем наличие аккаунта.

### Route guards

- `AuthGuard({ requireAuth })`:
  - `unknown` → скелетон;
  - `requireAuth` + не аутентифицирован → `/login`;
  - `!requireAuth` + аутентифицирован → `/(tabs)`.
- `RoleGuard({ allowedRoles })`: активная роль вне списка → редирект на
  первый экран своей роли (`firstRouteFor`).
- Обёрнуто: `(auth)/_layout` → AuthGuard(requireAuth=false) — кроме
  `/welcome` (онбординг нужен вошедшему без организаций, guard внутри
  самого экрана); `(tabs)/_layout` → AuthGuard(requireAuth=true);
  каждая ролевая группа `(tabs)/<role>/_layout` → RoleGuard;
  `/dev/design` → AuthGuard(requireAuth=false) + только `__DEV__`.

### Экраны

`(auth)/`: login (пароль + DEV-быстрый вход), register (валидация после
blur, чекбокс условий), otp (2 шага, таймер 60 с, маска 999-999),
reset-request / reset-confirm (сброс пароля), welcome (онбординг-заглушка
для пользователя без организаций). В профилях всех 4 ролей — выход с
подтверждением в нижнем шите.

### Расширения дизайн-системы (не токены)

- `Input`: `rightIcon` + `rightIconAccessibilityLabel` + `onRightIconPress`
  (глаз видимости пароля, зона ≥ 48×48).
- `Button`: `fullWidth` (alignSelf: stretch).

## Безопасность

- Пароли — только хеш, никогда в открытом виде, даже в моке.
- Токены — только в AsyncStorage (`bazar.auth.session`), никогда в URL
  и логах.
- OTP-коды — не в аналитике; вывод в консоль только в `__DEV__`.
- Logout — полная очистка всех ключей аутентификации и контекста.

## Открытые вопросы

- Реальный бэкенд: NestJS + JWT + refresh-token family — Промт 6.
- SMS-провайдер (Twilio, SMS.RU) — Промт 6.
- Полноценный онбординг (создание организаций/точек через UI) — Промт 5.
- Биометрия (Face ID / Touch ID) — следующий этап.
