# ADR 0008: Backend foundation и интеграция auth (Промт 7)

Дата: 2026-11-12
Статус: принято

## Контекст

До Промта 7 аутентификация и онбординг жили на AsyncStorage-моках
(`authMock`, Промт 2–3). Промт 7 требует реальный бэкенд: NestJS +
Prisma + PostgreSQL, Argon2id, JWT + refresh-token family, API
организаций и точек, и переключение mobile-auth на реальный API.

## Решение

### Стек

- **NestJS 11** + TypeScript strict. Структура модулей: auth, users,
  organizations, memberships, locations, prisma, health, seed.
- **Prisma 6** ORM. Схема: `User`, `Session`, `Organization`,
  `Membership`, `BusinessLocation` — минимальный набор Промта 7;
  Product/Order/Debt/Delivery — Промт 9+.
- **БД — SQLite (демо-fallback)**. Приоритет из промта: Neon
  (`secrets/.env.local` пуст — ключей нет) → локальный PostgreSQL
  через Docker (Docker и sudo в песочнице недоступны) → SQLite.
  Переключение на PostgreSQL/Neon — замена `DATABASE_URL` и
  провайдера в `schema.prisma`; код не меняется.
- **Аргон2id** (`@node-rs/argon2`): memoryCost=19456, timeCost=2,
  parallelism=1 — минимальная конфигурация OWASP. Хеш не покидает
  сервер (нет в ответах API и логах).

### Токены

- **Access — JWT HS256, TTL 15 минут**, payload `{ sub: userId }`.
  Роли не зашиваются: права проверяются по БД на каждом запросе.
- **Refresh — opaque** (32 байта base64url), в БД только SHA-256-хеш,
  TTL 30 дней. Хранится в AsyncStorage клиента (SecureStore —
  Промт 8); access — только в памяти.
- **Refresh-token family**: вход создаёт семью (UUID); обновление
  отзывает старую запись и создаёт новую в той же семье.
  **Reuse detection**: повторное использование отозванного токена
  отзывает всю семью (401) — защита от кражи токена.

### Auth API (`/api/auth`)

register, login, refresh, logout, me, otp/send, otp/verify.
Сверх списка промта добавлен **password/reset** (код + новый пароль,
отзыв всех сессий): существующий экран восстановления пароля mobile
(Промт 4) иначе ломался. [Требует подтверждения пользователя.]

OTP: in-memory хранилище, TTL 5 минут, 5 попыток; в
`NODE_ENV !== 'production'` код возвращается в ответе (`devCode`) —
демо-вход без SMS. SMS-провайдер — Промт 8.

### Organizations / Locations / Users API

- `POST/GET /api/organizations`, `GET /api/organizations/:id` —
  только участникам (чужие — 404 без раскрытия существования).
- `POST/GET /api/organizations/:id/locations`, `GET /api/locations/:id`.
  Порядок проверок создания точки: существование (404) → членство
  (404 чужим) → тип RETAIL (400) → роль STORE_OWNER (403).
- `GET /api/users/me` — профиль без токенов.
- Проверка прав — только на сервере; клиентская — UX-уровень.

### Rate limiting

`@nestjs/throttler`, in-memory: один бакет `default` 100/мин на IP;
переопределения: login/register/otp/reset — 5/мин, refresh — 30/мин,
чтение — 100/мин. Именованные бакеты v6 суммируются на каждом
маршруте — поэтому схема с одним бакетом и per-method `@Throttle`.
429 — общий формат ошибок, код `AUTH_RATE_LIMIT`, русский текст.
Redis-хранилище — открытый вопрос (мультиинстанс).

### Прочее

- **OpenAPI**: `/api/docs` (Swagger UI) + `/api/docs-json`.
- **Helmet**, CORS (same-origin в демо), pino-логи с requestId
  (AsyncLocalStorage). Тела и заголовки запросов не логируются —
  там пароли и токены.
- **Health**: `GET /api/health` → `{ status, db, version }` (SELECT 1).

### Деплой: один порт

Preview-шлюз платформы проксирует один порт. Поэтому **NestJS на
:3000 отдаёт и API (`/api/*`), и статику mobile** (ServeStaticModule
→ `apps/mobile/dist`, SPA-fallback для маршрутов Expo Router,
`exclude: ['/api/*splat']` — синтаксис path-to-regexp v8). Mobile
собран с `EXPO_PUBLIC_API_URL=/api` (относительный URL, same-origin).
Туннели запрещены (проверено ранее: блокируются политикой песочницы).

### Решение по authMock

**Удалён полностью** вместе с тестами (−27). Dev-fallback
`EXPO_PUBLIC_USE_MOCK_AUTH` не вводился: мёртвый код дороже.
Graceful degradation: при недоступном API экран `/login` показывает
`ErrorState` «Сервер временно недоступен» с кнопкой «Повторить»;
в мок приложение не падает.

### Решение по contextStore (переходный период)

`contextStore.syncWithUser` принимает «снимок мира»
`{ memberships, organizations, locations }`. Источник —
`GET /api/auth/me` (реальные членства Ивана). Локальные данные
онбординга (`onboardingMock.listForUser`) подмешиваются поверх —
созданные в онбординге организации живут до миграции онбординга на
API (Промт 8). Моки `mocks/context.ts` остаются только для
`customerContext` и онбординг-экранов.

`shortName` организаций вычисляется на сервере: «Сеть «У дома»» →
«У дома». Названия точек не сокращаются («Точка на Садовой»
целиком): склонение без морфологического анализатора дало бы
«Садовой» вместо «Садовая».

### Seed

Иван Петров (`+79001234567` / `qwerty123`, Argon2id): 4 организации
(Опт-Юг WHOLESALE, Сеть «У дома» RETAIL + 3 точки, Магазин «Ромашка»
RETAIL + 1 точка, Транс-Логистик LOGISTICS) и 4 членства. Идемпотентен.
`pnpm --filter @bazar/api seed`.

## Тесты

- Backend unit (49): auth.service (register/login/refresh/reuse/
  logout/me/OTP/reset), token.service (семьи, истечение, отзыв),
  otp.service, organizations.service (владелец, права, изоляция),
  mappers. Prisma подменён in-memory фейком.
- Backend e2e (16): полный флоу токенов, rate limit (6-й login → 429),
  изоляция организаций, OTP, сброс пароля, OpenAPI, health.
  SQLite `test-e2e.db`, `runInBand`.
- Mobile (226): обновлены authStore/экраны на мок authApi; новые
  client.test (авто-refresh, таймауты), authApi.test (маппинг).

## Последствия

- Вход Ивана в демо идёт через реальный backend (Argon2id, JWT,
  refresh-ротация) — публичный URL один: и приложение, и API.
- Перезапуск песочницы требует пересборки БД: миграции + seed
  (дев-БД не в git). Инструкция — в README apps/api.
- Ограничения SQLite: enum'ы эмулируются строками с проверкой в DTO;
  при переходе на PostgreSQL заменить на настоящие enum.
- Организации, созданные в онбординге, живут локально до Промта 8:
  после logout/login они подмешиваются к данным API, но на сервере
  их нет (в /api/auth/me не попадают).

## Открытые вопросы

1. SMS-провайдер для OTP (сейчас devCode в dev-ответе).
2. Redis для rate limiting (мультиинстанс; сейчас in-memory).
3. SecureStore для refresh-токена на нативных сборках (Промт 8).
4. HTTPS-only cookies для web-клиента (Промт 9).
5. Миграция онбординга на API организаций (Промт 8).
6. Подтверждение эндпоинта password/reset (добавлен сверх списка).
7. Перенос демо-БД на Neon/PostgreSQL при появлении ключей.
