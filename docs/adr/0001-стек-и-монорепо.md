# ADR 0001: Стек и монорепо

- **Статус:** принято (Промт 1, каркас проекта)
- **Дата:** 2026-11-10

## Контекст

Создаём новый проект «Bazar» (ранее «АгроМолл») с чистого листа: мобильное приложение аграрной торговой экосистемы. Прежний прототип v0.8.1 не переносится. Основные ограничения:

- mobile-first, web — только через Expo web;
- операционный контекст: рынок, 4–14 утра, перчатки, слабый свет, слабый сигнал, офлайн — норма;
- платформа не держит деньги; два торговых контура (опт и розница) не смешиваются;
- язык кода, комментариев, коммитов и документации — русский.

Нужен каркас, который позволит наращивать функциональность промтами, не переделывая фундамент.

## Решение

### Монорепо: pnpm workspaces + Turborepo

- `apps/` (mobile, api) + `packages/` (ui, types, validation, config).
- pnpm — быстрый, строгий lockfile, стандарт для RN/Expo-монорепо.
- Turborepo — кэширование и оркестрация задач `lint` / `typecheck` / `test` / `build`; в turbo v2 секция конфигурации называется `tasks` (прежнее имя `pipeline` удалено).
- В `.npmrc` задан `node-linker=hoisted`: предсказуемая «плоская» структура `node_modules` для Metro, Expo CLI, Jest и CI. Изолированный pnpm-линкер с симлинками периодически ломает разрешение модулей в RN-инструментарии.

### Мобильное приложение: Expo SDK 58 (managed) + React Native 0.88

- Managed workflow: без нативных папок `ios/` / `android/` в репозитории, запуск в Expo Go.
- Expo Router (file-based, `src/app/`) — официально рекомендованная навигация Expo.
- TypeScript strict, без `any` в новом коде (`@typescript-eslint/no-explicit-any` = error).
- Заранее установлены (не используются, по требованию Промта 1): Zustand (состояние), Reanimated + react-native-worklets (анимации).
- Приложение стартует с одного маршрута `/` — экран-заглушка «Bazar / Загрузка» со статичным плейсхолдером (спиннеры запрещены).
- В `app.json`: `userInterfaceStyle: light` (в этом промте только светлая тема), `web.output: static` (статический экспорт web-версии). Эксперименты `typedRoutes` и `reactCompiler` отключены до явного решения — уменьшает риск рассинхронизации типов в CI.

### Тесты: Jest 30 + jest-expo + @testing-library/react-native

- `jest-expo` — официальный пресет Expo (SDK 58), согласован с версиями React/React Native.
- RNTL v14 работает с новым пакетом `test-renderer` (замена устаревшего `react-test-renderer`).
- Smoke-тест `apps/mobile/__tests__/index.test.tsx`: экран `/` рендерится и содержит «Bazar» и «Загрузка».

### Качество: ESLint 9 (flat config), Prettier, Husky + lint-staged + commitlint

- **ESLint — flat config (`eslint.config.js`), а не legacy `.eslintrc.cjs`.** Обоснование: ESLint 9 использует flat config по умолчанию; legacy-формат объявлен устаревшим и удаляется в следующих мажорных версиях; `eslint-config-expo@58` официально поддерживает flat config (экспорт `eslint-config-expo/flat`). Это отклонение от изначального списка файлов Промта 1 — требует подтверждения пользователя.
- Правило `no-console`: warn, разрешены только `console.warn` и `console.error`.
- Prettier: 2 пробела, одинарные кавычки, точка с запятой, `trailingComma: all`.
- Husky: pre-commit → lint-staged (eslint --fix + prettier --write); commit-msg → commitlint (Conventional Commits, описание на русском).
- Общие tsconfig-пути: `@ui/*`, `@types/*`, `@validation/*`, `@config/*` (плюс `@/*` внутри mobile).

### CI: GitHub Actions

- Один job `quality`: pnpm install (cache) → `pnpm turbo lint typecheck test`. Падает при любой ошибке. Деплоя нет (по плану — отдельный промт).

### Прочее

- Репозиторий GitHub `bazar` создан **приватным** (безопасный дефолт для коммерческого проекта; публичность — решением владельца).
- Секреты — в `secrets/.env.local` (gitignored). В `.env.example` — только имена переменных без значений.

## Рассмотренные альтернативы

| Альтернатива                      | Почему нет                                                                                                  |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Bare React Native CLI             | Дольше настройка нативных проектов; Expo Go и managed workflow ускоряют итерации; нативный код не требуется |
| Nx / Lerna вместо Turborepo       | Nx тяжеловат для текущего масштаба; Lerna фактически не развивается; Turborepo минимален и достаточен       |
| npm / yarn workspaces вместо pnpm | Медленнее, менее строгая работа с зависимостями; pnpm — фактический стандарт Expo-монорепо                  |
| Legacy ESLint (.eslintrc.cjs)     | Устаревший формат, поддержка удаляется; пришлось бы фиксировать ESLint 8                                    |
| Vitest вместо Jest                | Jest — стандарт RN-экосистемы; jest-expo даёт готовый пресет под SDK                                        |
| Next.js / Vite для web            | Запрещено Промтом 1: web — только через Expo web                                                            |

## Последствия

- Изоляция pnpm отключена (hoisted) — чуть менее строгая, но предсказуемая для RN-инструментария структура `node_modules`.
- Пакеты `@bazar/ui`, `@bazar/types`, `@bazar/validation`, `@bazar/config` — пустые заготовки; базовые конфиги качества пока живут в корне репозитория, `@bazar/config` — точка расширения.
- Переименование продукта «АгроМолл» → «Bazar» отражено и на экране-заглушке, и в smoke-тесте (в тексте Промта 1 было «АгроМолл») — требует подтверждения пользователя.

## Открытые вопросы

1. Дизайн-токены и типографика — Промт 2 (сейчас на экране-заглушке временные цвета из операционного контекста).
2. Стек API (`apps/api`) и база данных — отдельный промт.
3. Сборка и публикация (EAS или self-hosted) — отдельный промт после настройки API.
4. Включать ли `typedRoutes` / `reactCompiler` из Expo SDK 58 — после стабилизации каркаса.
5. Брендинг-ассеты (иконка/сплэш) — пока шаблонные из Expo-шаблона.
