# ADR 0018: Логирование — ring-buffer, тост с копированием, контракт полей

**Статус:** принят (Промт 18, Часть A)
**Контекст:** поддержка поле в 4 часа утра. Когда у продавца «не
работает приложение», инженер получает от него скриншот — и всё.
Серверные pino-логи уже были (Промт 7), но клиентская сторона
была чёрным ящиком: сетевые сбои, падения экранов и 5xx
терялись молча. Нужен был способ получить от пользователя
«журнал» одним нажатием — без аккаунтов, почты и сторонних
сервисов (Sentry и аналоги тянут SDK, сеть и ключи).

## Решения

### 1. Клиент — ring-buffer в памяти, 100 записей

`apps/mobile/src/utils/logger.ts`:

- `error` — буфер + `console.error` + **тост с кнопкой
  «Скопировать лог»**. Кнопка копирует весь буфер (JSON) в
  clipboard; нажатие **закрепляет** тост (автоскрытие
  останавливается — иначе кнопка исчезает до того, как её нажали).
- `warn` — буфер + console, без тоста: 4xx — ожидаемые бизнес-отказы
  («не хватает остатка»), тостом дёргать нельзя.
- `info` — только в `__DEV__`-сборках.
- Запись: timestamp, level, action, message, context?, а также
  userId/screen из `logger.setContext` (проставляет authStore).

### 2. Тост с действием — расширение дизайн-системы

`Toast` (packages/ui) получил необязательное `action: { label, run }`:
кнопка в карточке (зона ≥48), `runCurrentAction` выполняет действие
и ставит `pinned: true` — таймер автоскрытия больше не
запускается, закрытие только тапом по карточке. Обратная
совместимость: без action поведение прежнее.

### 3. Clipboard без новых пакетов

`utils/clipboard.ts`: web — `navigator.clipboard` + фолбэк на
скрытую textarea (старые webview), native — честный `false`
(пакет не тянем; product-сборка — веб-экспорт).

### 4. Экран /dev/logs — доступен ВСЕХ сборках

В отличие от `/dev/design` (только `__DEV__`), журнал открывается и
на проде прямым URL: секретов не содержит, ссылок из навигации
нет. Это осознанное решение: DoD промта требует диагностику на
публичном URL. Список (новые сверху), «Очистить», «Скопировать всё».

### 5. Бэкенд — контракт полей HTTP-лога

`pinoHttp` заменён явным middleware на событии `finish`
(зарегистрирован внутри requestId-контекста — AsyncLocalStorage
доводит store до слушателя):

```
{ requestId, userId, action: "POST /api/orders", method, url,
  status, duration_ms }
```

- `userId` — `sub` из JWT **без верификации** (только для логов;
  аутентификацию делают guard'ы), defensively ограничен.
- Семантические `action` — события сервисов: `auth.login`,
  `order.created`, `stock.movement`.

## Чего в логах НЕТ никогда

Пароли, OTP-коды, refresh-токены, полные номера телефонов
(маска `+7900***4567` через `maskPhone`), тела запросов и заголовки.

## Отклонённые альтернативы

- **Sentry/Crashlytics** — внешний SDK, сеть, ключи; против
  ограничений проекта (демо без внешних зависимостей).
- **Персистентный журнал (AsyncStorage)** — переживает перезапуск,
  но копится и требует управления размером; ring-buffer в памяти
  достаточно для сценария «показал экран → скопировал → отправил».
- **Тост на каждый warn** — шум; 4xx — рабочие отказы бизнеса.
