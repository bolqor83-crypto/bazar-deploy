# ADR 0006: Веб-платформа — скелет @bazar/web

- **Статус:** принято (Промт 6, часть C)
- **Дата:** 2026-11-11

## Контекст

Bazar — mobile-first, но у проекта есть веб-будущее: розничная витрина
для покупателей. Промт 6 требует подготовить место веб-платформы в
монорепо, **не** реализуя её: Next.js появится в Промте 7.

## Решение

Пакет `apps/web` (`@bazar/web`) — скелет:

- `package.json` без рантайм-зависимостей; единственный скрипт —
  `typecheck: tsc --noEmit`;
- `tsconfig.json` наследует общий `tsconfig.base.json` (strict);
- `src/index.ts` — точка входа-заглушка;
- `README.md` — план на Промт 7 и правила.

Next.js сознательно **не** устанавливаем: пустой пакет не тянет
сборку, не создаёт поломанных конфигураций и не иллюстрирует
готовность. `pnpm-workspace.yaml` уже покрывает `apps/*` — изменений
не потребовалось.

## Конвейер

Скрипт `typecheck` подхватывается turbo: конвейер вырос с 12 до
**13 задач**. Когда появится Next.js, добавятся `build`/`lint`/`test` —
по тем же правилам, что и остальные пакеты.

## Правила на будущее (Промт 7)

- Веб-платформа не опережает мобильное приложение.
- Дизайн — только токены `@bazar/ui`; отдельные стили запрещены.
- Сторы, рассчитанные на RN, требуют SSR-безопасных обёрток
  (паттерн `getSafeStorage` из `contextStore`).
