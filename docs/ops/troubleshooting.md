# Troubleshooting — частые проблемы

## «Rate limit на логин»

- Симптом: 429 на `/api/auth/login` (или register/otp/reset).
- Причина: более 5 попыток за минуту с одного IP (защита от
  перебора, Промт 7).
- Что делать: **подождать 1 минуту**. В тестах throttler выключен
  (`THROTTLER_DISABLED=true`), отдельный rate-limit.e2e-спек
  проверяет лимиты явно.

## «401 после деплоя»

- Симптом: все запросы с валидным токеном падают 401 сразу после
  выкладки.
- Причина: сменился `JWT_ACCESS_SECRET` в окружении Render (или
  его нет) — старые access-токены больше не подписываются тем же
  ключом.
- Что делать: проверить **Settings → Environment** сервиса
  `bazar` в Render: `JWT_ACCESS_SECRET` (одна и та же строка
  ≥32 символов; значение не выводить), `DATABASE_URL_*`. После
  правки — Manual deploy. Пользователи просто перелогинятся:
  refresh-семьи в БД переживают рестарт, access живёт 15 минут.

## «Миграции не применились»

- Симптом: 500 на новых эндпоинтах, в логах
  `P2021 table does not exist` / `P2022 column does not exist`.
- Причина: Render задеплоил код, но `prisma migrate deploy` не
  прошёл (или БД ещё спала).
- Что делать: локально против прод-БД:
  ```bash
  cd apps/api
  DATABASE_URL_DIRECT="<прод-direct-URL>" npx prisma migrate deploy
  ```
  Проверить: `npx prisma migrate status`. Никаких
  `migrate dev`/`db push` на проде — только deploy.

## «Golden не совпадают» (pixelmatch красный)

- Симптом: джоба «pixelmatch golden (tolerance 0.5%)» красная,
  артефакт `pixelmatch-diff` показывает кадры с % > 0.5.
- Причины и порядок:
  1. **Осознанно изменили экран** → переснять: локально
     `pnpm golden:update` (поднимает сервер + снимает кадры),
     глазами проверить новые эталоны, закоммитить PNG.
  2. **Данные съехали** (seed поменялся, заказы создались) →
     проверит подготовку в `scripts/visual/` (prep-сценарии),
     переснять после фикса подготовки.
  3. **Транзиент** (Neon 500 при prepare) → CI уже делает retry;
     если снова — Re-run jobs.
- Правило: позиции оптовиков, seed-данные, влияющие на кадры,
  менять без пересъёмки нельзя (ADR 0017).

## «Приложение не грузится / белый экран»

- Открыть `/dev/logs` (журнал клиентских логов, работает и на
  проде): сетевые ошибки и падения будут в буфере; кнопка
  «Скопировать всё» отдаёт JSON для передачи в поддержку.
- Проверить `/api/health`: если он не отвечает ~90 с — прод
  спит (free tier), повторить.
- 5xx видны в тосте «Ошибка» с кнопкой копирования лога.

## «e2e падают локально»

- Проверить `apps/api/.env`: URI Neon (direct для транзакций).
- Схема `bazar_test` пересоздаётся global-setup'ом — параллельно
  два прогона гонять нельзя (гонка, см. runbook).
- Чанками: `npx jest --config test/jest-e2e.config.cjs --runInBand
--testPathPattern "(auth|cart)"`.

## «Проверка качества» падает на typecheck после правок UI

- Компоненты и токены меняются в `packages/ui` → прогнать
  `pnpm turbo lint typecheck test --concurrency=2` локально до
  коммита; CI гоняет то же самое.
