# AGENTS.md — правила проекта «Bazar»

Правила обязательны для всех последующих промтов, агентов и контрибьюторов.

## Проект

- «Bazar» (ранее «АгроМолл») — новая цифровая торговая экосистема аграрного рынка.
- Это **новый проект с чистого листа**. Прежний прототип (v0.8.1 и любые старые версии «АгроМолла») — не читать, не копировать, не импортировать, не мигрировать. Ничего из него.
- Всё, что не описано в текущем промте, — не проектировать и не реализовывать заранее. Ждём следующих промтов.

## Язык

- Код, комментарии, коммиты, документация, задачи и отчёты — на русском языке.
- Идентификаторы в коде (имена переменных, функций, типов) — на английском; весь текстовый контент — на русском.

## Платформа

- Mobile-first: основная цель — мобильное приложение (Expo + React Native).
- Web-версия — только через Expo web. Next.js, Vite, CRA и другие веб-фреймворки не использовать.

## Деньги

- Платформа **не принимает и не распределяет деньги**. Только фиксирует факты оплаты между участниками.
- Никакого эскроу, никаких кошельков, никаких транзакций на платформе.

## Торговые контуры

- Два контура, которые нельзя смешивать:
  - **оптовый** — публичный оптовый каталог, оптовые заказы;
  - **розничный** — витрины торговых точек, розничные заказы.
- Контуры не смешивать ни в UI, ни в данных.

## Операционный контекст пользователя

- Пользователь работает в **4–14 утра на рынке**: в перчатках, при слабом свете, со слабым сигналом.
- Зоны нажатия **≥ 48×48 pt**, шрифт body **≥ 17pt**, высокий контраст, крупные кнопки — в нижней трети экрана.
- **Офлайн — норма, а не крайний случай.** Онлайн-первый клиент неприемлем.
- Цвета (операционный контекст, не финальные токены):
  - тёплый крем `#FAF8F4` — база;
  - глубокий зелёный `#2E6B4E` — бренд;
  - янтарь `#C58A24` — предупреждение/срочность;
  - терракот `#B85C4A` — destructive.
- **Красный цвет (`#FF0000` и близкие оттенки) НЕ использовать нигде и никогда.**
- **Спиннеры запрещены.** Для состояний загрузки — только Skeleton / shimmer.

## Технологический стек

- Монорепо: pnpm workspaces + Turborepo.
- Мобильное приложение: Expo (managed) + React Native + TypeScript strict (без `any` в новом коде).
- Навигация: Expo Router (file-based).
- Состояние: Zustand. Анимации: Reanimated.
- Бэкенд (Промт 7): NestJS 11 + Prisma 6 + Argon2id + JWT.
- Тесты: Jest + jest-expo + @testing-library/react-native (mobile);
  Jest + ts-jest + supertest (api, unit и e2e).
- Новые npm-пакеты — только с явного разрешения пользователя.
- Секреты хранятся только в `secrets/.env.local` и `apps/api/.env` (gitignored). Никогда не коммитить и не выводить их значения.

## Контекст и навигация (Промт 3, ADR 0003)

- Контекст: User → Organization → BusinessLocation. Уровни не склеивать.
- Переключение контекста — через шапку (ContextSwitcher → ContextSheet),
  не через отдельный экран логина.
- Tab bar зависит от активной роли (4 роли: покупатель, владелец точки,
  оптовик, перевозчик).
- Оптовый и розничный контуры разведены по контексту, не по приложениям;
  в одном tab bar не смешиваются.
- Экраны-заглушки используют EmptyState с осмысленным текстом (не «Нет данных»)
  и не обещают несуществующую функциональность.
- Активный контекст персистится (ключ `bazar.context.active`); невалидный
  контекст откатывается на роль покупателя.

## Аутентификация (Промт 7, ADR 0004 + 0008)

- Аутентификация — реальный API (`apps/api`, NestJS): login /
  register / OTP / refresh / logout / сброс пароля.
- Пароли — Argon2id на сервере (OWASP: 19 МБ / 2 итерации),
  хеш не покидает бэкенд.
- Access-JWT (HS256, 15 минут) — только в памяти клиента;
  refresh (opaque, 30 дней) — в AsyncStorage `bazar.auth.refresh`
  (SecureStore — Промт 8). В БД — только SHA-256-хеш.
- Refresh-token family + reuse detection: повторное использование
  отозванного токена отзывает всю семью.
- Клиент `src/services/api/client.ts`: авто-refresh при 401 (одна
  попытка), таймаут 15 с, структурированные ошибки с кодами.
- Гидратация: refresh → `GET /api/auth/me`; после входа контекст —
  по приоритету членств wholesale → store_owner → carrier → customer.
- Демо-пользователь: Иван Петров, `+79001234567` / `qwerty123`
  (4 организации в реальной БД, seed).
- OTP в dev-режиме сервера возвращается в ответе (`devCode`) и
  показывается на экране только в `__DEV__`.
- Мок-auth удалён (ADR 0008). При недоступном API — ErrorState
  «Сервер временно недоступен» с «Повторить»; в мок не падаем.

## Онбординг (Промт 6, ADR 0005)

- Онбординг — группа `(onboarding)`: welcome → role → organization →
  (store_owner) location → done. Путь `/welcome` принадлежит ей,
  в `(auth)` его больше нет.
- Пост-аутентификационную маршрутизацию выполняет ТОЛЬКО AuthGuard:
  с членствами → `/(tabs)`, без членств → `/welcome`. Экраны входа
  сами навигацию не делают (фикс Бага №2, гонка с Redirect).
- Членство создаётся только в `finish()` — брошенный онбординг
  возобновляется (OnboardingGuard пускает пользователя без членств).
- Прогресс персистится: `bazar.onboarding.state` (шаг, роль, черновики,
  id созданных сущностей). Черновики форм подставляются при возврате.
- Сущности онбординга: `bazar.onboarding.organizations/locations/
memberships`; // MOCK ONLY. Миграция онбординга на API — Промт 8.
- contextStore держит «снимок мира» (memberships + organizations +
  locations). Источник — `GET /api/auth/me` (Промт 7); локальные
  онбординг-данные подмешиваются поверх (`onboardingMock.listForUser`)
  до миграции. Моки `mocks/context.ts` — только для customerContext
  и онбординг-экранов.
- `logout` сбрасывает и онбординг: черновики не протекают между
  аккаунтами.

## Веб-платформа (Промт 6, ADR 0006)

- `apps/web` (`@bazar/web`) — скелет без рантайм-зависимостей:
  только typecheck. Next.js и витрина — Промт 7.
- Веб не опережает мобильное приложение; дизайн — только токены
  `@bazar/ui`.
- Конвейер turbo — 16 задач (13 + @bazar/api lint/typecheck/test).

## Бизнес-компоненты (Промт 6, ADR 0007)

- 10 presentation-компонентов в `@bazar/ui`: PriceDisplay,
  QuantitySelector, StockIndicator, OrderStatus, ProductCard,
  ProductRow, OrderSummary, PartyCard, LocationSelector,
  DeliveryCard. Данные — только пропсами, без моков внутри.
- Деньги — целые копейки; отображение через `formatPrice`:
  узкий неразрывный пробел U+202F, запятая, табличные цифры.
- Скидки — янтарь (warning), опасное — терракота; красный запрещён.
- Статусы заказа: 11 значений, русские подписи в
  `ORDER_STATUS_LABELS`, цвета не выбираются экранами.
- Витрина `/dev/design` содержит секцию «Бизнес-компоненты»
  (обе темы); витрину не удалять.

## Визуальные стандарты (Промт 8, ADR 0009)

Обязательны для каждого следующего промта; проверяются скриптом
`pnpm lint:visual` (`scripts/check-visual-rules.mjs`, входит в приёмку).

- Красный запрещён (#FF0000/#E74C3C/#DC3545): опасное — терракота,
  предупреждения — янтарь.
- ActivityIndicator/Spinner запрещены: загрузка — только Skeleton.
- Эмодзи в UI запрещены: иконки — Lucide, шрифт — Inter.
- Рамки вместо теней; зоны касания ≥ 48×48; основной текст ≥ 17pt;
  контраст WCAG AA; тёмная тема — полноценная, не инверсия.
- Три вьюпорта на скриншотах: 360×800, 390×844, 430×932 — светлая
  и тёмная темы.
- Роли имеют свой акцент: покупатель — фото и витрина, владелец
  точки — цифры и таблицы, оптовик — партии и цены, перевозчик —
  маршруты.
- Пустые состояния — обещание + действие (кнопка), а не текст про
  внутреннюю кухню («когда будет API» запрещено).
- Деструктивные вторичные действия (выход) — текстовые кнопки
  терракотой, не кричащие заливки; подтверждение — в диалоге.
- Golden-скриншоты (22 экрана, Промт 9): `docs/visual-golden/` в
  репозитории — это контракт вёрстки. Переснятие — только вручную
  (`pnpm golden:update`, точечно `scripts/golden-one.mjs <name>`)
  с review `git diff` и коммитом; CI гоняет pixelmatch с
  tolerance 0.5% на каждый push.
- Заглушки изображений — пастельные тона `tokens/placeholder.ts`
  (одинаковые в обеих темах), до настоящих фото (Промт 9).

## Безопасность

- Пароли — Argon2id на сервере; никогда не в открытом виде, хеш не
  покидает бэкенд.
- Access-токен — только в памяти клиента; refresh — AsyncStorage,
  в БД — SHA-256-хеш. Токены не в URL и не в логах.
- Rate limiting на auth: 5/30/100 запросов в минуту по группам.
- Права проверяются на сервере; чужие организации — 404 без
  раскрытия существования.
- OTP-коды не попадают в аналитику.
- Сущности онбординга создаются от id аутентифицированного
  пользователя; поля `createdBy` пишутся всегда.
- Не выводить секреты в отчёты и логи.

## Бэкенд (Промт 7, ADR 0008)

- `apps/api` (`@bazar/api`): NestJS 11 + Prisma 6, TypeScript strict.
- Модель: User → Organization → Membership → BusinessLocation → Role.
  Product/Order/Debt/Delivery — Промт 9+, не создавать раньше срока.
- БД демо — SQLite (Docker/PostgreSQL в песочнице недоступны);
  переход на Neon/PostgreSQL — замена DATABASE_URL + провайдера.
- OpenAPI на `/api/docs` (Swagger UI) и `/api/docs-json` — контракт
  для генерации клиента.
- Структура ответа ошибок: `{ statusCode, error, message, code }` —
  код машиночитаемый, клиент маппит в русские тексты.
- Логи pino с requestId (AsyncLocalStorage); тела и заголовки
  запросов не логируются (там пароли и токены).

## Деплой (Промт 7)

- Один публичный URL через preview-шлюз платформы: NestJS на :3000
  отдаёт и API (`/api/*`), и статику mobile (ServeStaticModule →
  `apps/mobile/dist`, SPA-fallback).
- Mobile собирается с `EXPO_PUBLIC_API_URL=/api` (same-origin).
- Туннели (cloudflared/localtunnel/ngrok) заблокированы политикой
  песочницы — не пробовать.
- После перезапуска песочницы: `pnpm install` → `prisma migrate dev`
  (накатит seed) → `pnpm --filter @bazar/api build` → запуск
  `node apps/api/dist/src/main.js` на :3000.

## Инфраструктура (разрешено с Промта 9)

Прежние ограничения серии промтов («git push в GitHub запрещён»,
«токены не использовать», «деплой запрещён») **отменены явным
разрешением пользователя в Промте 9**.

- **GitHub push разрешён.** Токен — в `secrets/.env.local`
  (gitignored). Репозиторий `bazar` — приватный.
- **Neon PostgreSQL** — production-БД (pooled — runtime,
  direct — миграции). SQLite — только локальный fallback без сети.
- **Render** — только для Промта 10. Токен сохранить, API не вызывать
  до Промта 10.
- **Pixelmatch CI** — разрешён и обязателен (Промт 9).
- Секреты — `secrets/` (gitignored, `secrets/.gitignore` гасит всё
  кроме себя) и `apps/api/.env` (gitignored).
- `secrets/git-cred-helper.sh` — credential helper для push: токен
  не хранится в `.git/config` plaintext.
- **Никогда не выводить значения токенов** в отчёт, логи, коммиты.

## Защита маршрутов

- Каждая группа маршрутов обёрнута в AuthGuard, каждая ролевая группа —
  в RoleGuard (`(tabs)/<role>/_layout.tsx`).
- `/dev/design` доступен только в `__DEV__`-сборках.

## Definition of Done (для каждого промта)

- [ ] `pnpm install` проходит без ошибок и предупреждений.
- [ ] `pnpm turbo lint typecheck test` — зелёный.
- [ ] CI (GitHub Actions) — зелёный.
- [ ] Новая функциональность покрыта тестами.
- [ ] Коммиты — Conventional Commits на русском языке.
- [ ] Документация обновлена (README, ADR — при архитектурных изменениях).
- [ ] Секреты не попали в репозиторий (`git ls-files` не содержит `.env`-файлов).
- [ ] UI-изменения соответствуют операционному контексту (контраст, размеры, офлайн-поведение).
